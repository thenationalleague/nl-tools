NL Tools — Style Guide

Canonical visual reference for /system/nl-brand.css and /system/nl-utils.js. Preview font and spacing changes here before deploying, and use it to settle "is X already a brand token?" before adding a tool-local one.

Colours
1 · Brand — exactly four

The official NL brand is precisely these four: NL red, NL navy, white, black. Red and navy always take white text; never gold. Everything below this tier is a working colour with a job, or a stored fact — not brand.

The ladders are the canonical "lighter/darker than brand" — solid stops computed once in OKLab, committed as hex (hover over a stop for its value). By stop: 50/100 tinted surfaces · 200/300 light borders, idle hovers · 400 mid accents · 600 solid-button hover · 700/800 deep emphasis · 900 brand-tinted near-black. No rgba() overlay tokens exist, by design — a semi-opaque value composites differently on every background and won't render in canvas exports. "White on navy at 18%" is a solid --navy-400.

One reusable hue per job — each earns its place by doing exactly one thing. Swatches show base · -light (pill/card tint). Where a hue carries a -deep, that is an accessibility ink for text on the -light tint — a color-mix derivative noted on its parent's row, not a palette addition. Select — .nl-select

Use for a <select> standing alone in a control bar next to buttons. Not for one inside a .form-group — canon's form styling already covers that; not for choosing a club — that's the Club Picker.

The dropdown arrow is redrawn (via appearance: none + two gradients in --text-muted) because the platform's own arrow renders at a different size and colour on every OS and reads as unstyled next to brand buttons. Canon sets no width — set min-width locally if the layout needs it.

Icon-only buttons — .btn--icon

Use for row affordances where space denies a label: the edit pencil at the end of a person row, a nav arrow, a bare add. Not for primary page actions — those get a labelled .btn. It is a shape modifier only: pair it with a colour variant rather than restating colours, and it composes with all of them.

One size (30px), deliberately. It sets no fill and no stroke, so both halves of the sprite survive inside it — stroked UI glyph left, filled match glyph right. A wrapper that states either one flattens the other, which is how a hand-rolled version drew an invisible pencil.

<!-- The aria-label is not optional. There is no text node in an
     icon-only button, so without it a screen reader announces
     "button" and nothing else. All three callers set one. -->
<button class="btn btn--icon btn--ghost" aria-label="Edit this entry">
  <svg class="icon"><use href="/assets/icons/sprites.svg#icon-edit"></use></svg>
</button>

Passcode Gate

Use for a tool outside the portal that admits people by a code (uw-promo, programme, commercial-benchmarking, club-directory). Not for Firebase-account tools — that's auth-guard.js + the topbar. The code renders in Carbona ExtraBold at letter-spacing: 0.3em, the one place in the brand where tracking is deliberately extreme, so a half-typed code reads as separate characters rather than a word.

A gate is a UI boundary, not a security one. Validate the code server-side and exchange it for a token the RTDB rules can check (see functions/programme.js). A rule of ".write": "auth != null" behind anonymous sign-in admits anyone who opens the page.

Render it with NL.codeGate (nl-utils v1.29) rather than by hand. It draws this card, handles the keystrokes and submits on the last character, then runs the verify(code) you pass it — and it makes no security claim of its own, which is why verify has no default and throws if you omit it. NL.codeGate.viaFunction(root) is the one that is a real boundary: the code goes to a server, is never checked in the browser, and comes back as a custom token. It is named and kept separate so nobody adopts the screen and assumes they inherited the boundary with it. What follows a successful gate is .nl-idbar — see Entry Route above.

Tables — wrap, density & alignment

Wrap any table that can exceed its container in .table-wrap — it scrolls the table within the page (momentum scrolling on touch) instead of letting it stretch the viewport sideways. Not for intentionally-fixed layouts (a calendar grid sized to its viewport, a canvas export stage). Every table demo on this page sits in one; drag the compact demo below on a narrow window to see it scroll. The wrap carries no border or shadow of its own — .table owns its chrome; a tool wrapping a chrome-less custom table adds its surface as tool skin.

Use .table--compact for long scan-lists where rows-per-screen beats touch comfort. Not for ordinary data tables — default .table. Every declaration in the .table block is !important, so a tool cannot change row padding or column alignment from its own stylesheet — these modifiers are the supported way to do both.
